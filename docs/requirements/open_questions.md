## 1. 使い方

- 要件文書（00〜06）の中で推測で埋めなかった事項をここに集める。各質問に ID（Q-01…）を振り、関係する要件 ID を書く。ID は振り直さない。
- 仮置きが必要な箇所は、要件文書側に「仮: …」と書き、この文書の該当 Q を参照する。回答が得られたら要件文書を更新し、該当 Q を「6. 回答済み」に移す。一部だけ回答があった質問は、本文を書き換えて残す。
- GA4 側の事実（タイムゾーン、プロパティ作成日、データ保持、カスタム次元、拡張計測、月間の規模、デバイス比、市の粒度、イベント名）は、2026-11-03 に依頼者が GA4 Admin API と Data API を読み取り専用で実行した確認スクリプトの結果で回答した（Q-05、Q-07、Q-10 の 2、Q-11、Q-25。§6）。事実の本文は 03_data_sources.md §2.6 と 00_overview.md §4 にある。
- 優先度の意味
  - 高: 回答がないと設計に入れない、または公開範囲・安全性に関わる。
  - 中: 設計の途中までは仮置きで進められるが、構築前に確定が必要。
  - 低: 構築後でも変更しやすい。初回公開までに確定すればよい。

### Q-29 「普通の記事」「これから」という文言をライター 2〜3 人に見せてよいか（新規）

- 関係: FR-17、FR-21、FR-23、FR-31、NFR-94、NFR-97、M-19、M-24、M-27、docs/glossary.md
- 質問: 帯の 3 区分の文言「よく読まれています（上位 25%）」「多くの記事と同じくらい（中央 50%）」「これから（下位 25%）」と、「普通の記事」「真ん中の記事」という言い方を、公開前にライター 2〜3 人に下書きとして見せて受け取り方を確かめてよいですか。誰に見せるかを教えてください。
- テストに含めるもの（2026-11-03 追加、画面レビュー §7・§8-2）:
  1. 帯の 3 区分の文言の 2 案。案 A（現行）「よく読まれています / 多くの記事と同じくらい / これから」。案 B「よく読まれています / 多くの記事と同じくらい / ゆっくり読まれています」（「これから」は未来の語だが値は 30 日時点で固定されるので、古い記事にも通る言い方として比べる）。
  2. 帯の注記（新着記事の立ち上がり、記事詳細、著者サマリに共通）: 「3 つの区分は、同じ日数がたった記事を 4 等分したものです。4 本に 1 本は『よく読まれています』に、4 本に 1 本は『これから』に入ります。成績ではなく、位置です。」
  3. 1〜2 年前の記事に下の区分（「これから」）が付いた例。古い記事で意味が通るか、責められていると感じるか。
  4. 記事詳細（FR-23）の見出し「この記事はどう読まれた？」（旧「この記事は普通より読まれた？」）。
  5. 著者サマリ（FR-31 (b)）の統合文: 「◯◯さんの記事は、公開から 30 日で だいたい ◯回読まれています。多くの記事は ◯〜◯回（真ん中は ◯回）です」。
- 退避案（反応が悪かったとき。2026-11-03 追加、画面レビュー §3）: 新着記事の立ち上がり（FR-21）で行ごとの帯の文言をやめ、表の上に「多くの記事は 7 日で ◯〜◯回、30 日で ◯〜◯回」の 1 行を置く（比較の相手は残る）。FR-21 は期間内の新着全記事に著者名が付く唯一の帯つき一覧で、最も「誰が下か」が見えるため。採る場合は FR-21 の要件変更になる。現時点では FR-21 は変えない。
- 仮置き: 案 A の文言で進める。記事詳細の見出しは「この記事はどう読まれた？」、著者サマリは 5 の統合文で進める。
