# 未確定事項と依頼者への質問

- 状態: 草案
- 更新日: 2026-11-03

## 1. 使い方

- 要件文書（00〜06）の中で推測で埋めなかった事項をここに集める。各質問に ID（Q-01…）を振り、関係する要件 ID を書く。ID は振り直さない。
- 仮置きが必要な箇所は、要件文書側に「仮: …」と書き、この文書の該当 Q を参照する。回答が得られたら要件文書を更新し、該当 Q を「6. 回答済み」に移す。
- 優先度の意味
  - 高: 回答がないと設計に入れない、または公開範囲・安全性に関わる。
  - 中: 設計の途中までは仮置きで進められるが、構築前に確定が必要。
  - 低: 構築後でも変更しやすい。初回公開までに確定すればよい。

## 2. 優先度 高

### Q-01 「アクセス数」は何を指すか

- 関係: M-01、M-02、M-03、FR-10、docs/glossary.md
- 質問: 運営者とライターが「アクセス数」と言うとき、次のどれを指しますか。
  - (a) 表示回数（GA4 の screenPageViews。ページが表示された回数。同じ人が 3 回読めば 3）
  - (b) セッション数（GA4 の sessions。訪問の回数）
  - (c) ユーザー数（GA4 の activeUsers。訪問した人の数）
- 仮置き: (a) 表示回数を「アクセス数（PV）」として主指標にし、セッションとユーザー数は補助指標として併記する。
- 補足: ユーザー数は日別の値を足し合わせても期間のユーザー数にならない（同じ人が複数日に来ると重複する）。主指標にすると期間ごとの集計の作りが複雑になる。

### Q-02 小さな数を伏せるしきい値

- 関係: NFR-33、FR-73、06_acceptance.md
- 質問: 集計値が小さいとき、個人の行動が推測されないように格納時に伏せます。しきい値をいくつにしますか。また、伏せたときの表示は「5 未満」のような表記でよいですか。
  - 候補の例: 5、10。小さいほど多くの数字が見えるが、記事×地域×デバイスのように細かく切ったときに個人の行動が推測されやすくなる。
- 仮置き: 未確定。要件では「しきい値 T（未確定）」と書き、設計では設定値として外に出す。
- 補足: 伏せるのは「細かい次元で切った値」で、サイト全体の日別 PV のような大きな集計には通常かからない。

### Q-03 ライター同士の順位表と、本人による非表示の申し出

- 関係: FR-30、FR-35、FR-36、FR-51、NFR-36
- 質問:
  1. ライターを PV などで並べた順位表を出してよいですか。既定（security.md）は「出さない。全体の中央値・四分位との比較だけ」です。
  2. 著者別の公開本数（PV を含まない）を並べて表示することは順位表に当たりますか。
  3. ライター本人が「自分の数値を BI に出さないでほしい」と申し出たとき、それに応える仕組みが要りますか（要るなら、申し出の受け付け方は運営経由でよいか）。
  4. ライター別ビューの入口は、著者一覧から誰でも選べる形でよいですか。それとも、各ライターが自分の URL だけを知っている形にしますか（ログインなしなので、URL を知れば誰でも見られる点は変わりません）。
- 仮置き: 順位表は出さない。著者別の公開本数は表示する。非表示の申し出には、設定ファイルで著者を除外できる仕組みで応える。著者一覧は表示する。

### Q-04 公開の形（検索エンジンに載せるか）

  - (b) URL を知る人だけ。検索エンジンには載せない（noindex、robots で拒否）。ログインはないので、URL が広まれば誰でも見られる。
- 仮置き: (b)。

### Q-13 更新の鮮度の許容

- 関係: DS-01、M-09
