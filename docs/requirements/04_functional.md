## 1. 要件の書き方と優先度

- 要件 ID は FR-xx。後工程（設計・テスト）が参照するので振り直さない。削除するときは「廃止」と残す。
- 優先度
  - 必須: 初回公開に含める。
  - 高: 初回公開に含めたいが、未確定事項の回答やデータの確認待ち。
  - 中: 初回公開後でもよい。
  - 低: 要否を含めて未確定。
- 画面案は親エージェントの提案で、依頼者は異議なしだが個別の承認は未取得。確認が要るものは open_questions.md の Q-xx を参照する。
- 各要件に関係する指標 ID（M-xx）と非機能要件 ID（NFR-xx）を書く。
- 画面の言葉は 02_metrics.md の「画面での名称」と docs/glossary.md §1 に従う。表示と言葉の規則（1 画面 1 つの問い、比較の相手を添える、個人の数字に良し悪しの色を使わない、既定の期間は直近 28 日、スマホでは表は 4 列程度、説明文を画面に埋め込む）は NFR-94〜NFR-99。
- 前提: ログインがないので、ライター本人のページを他のライター・読者・運営が同時に見る。「見られて困る数字を出さない」より「見られても責められない形にする」を狙う（advice §5）。
- 技術選定（フレームワーク、ライブラリ、グラフの種類の実装）は書かない。構成（GitHub Actions → Supabase → Vercel）は依頼者の決定として制約に書く（00_overview.md §5）。

## 4. 記事一覧と記事ランキング（FR-20〜FR-25）
