# 06 受入基準

- 状態: 草案
- 更新日: 2026-11-03

## 1. 受入の進め方

- 要件 ID（M-xx、FR-xx、NFR-xx）ごとに「何をもって満たしたとするか」を書く。設計のテスト計画とトレース表はこの文書を参照する。
- 確認方法の種別
  - 目視: 画面で確認する。
  - 照合: GA4 の管理画面（標準レポートまたは探索）や WP REST API の値と比べる。GA4 との照合は、確定した期間（基準日の 8 日以上前）で行う。
  - 検査: Supabase の格納内容、ソースコード、設定、ログを調べる。
  - 試験: 自動テストまたは手動の操作で確かめる。
- 対象サイトと本番の BI に対して、スキャンや負荷試験などの能動的な試験はしない（NFR-72）。性能の確認は本番相当の構成で、通常の閲覧操作の範囲で行う。
- 仮置き（Q-xx）が残る要件は、仮の値で受入を行い、確定後に再確認する。
- 受入の記録は、要件 ID、確認日、確認者、結果、証跡（スクリーンショットや検査結果の要約。行データや秘密情報は含めない）を残す。
