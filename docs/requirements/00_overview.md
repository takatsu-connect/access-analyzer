## 1. 背景

- 「高津コネクト」（https://takatsu-connect.com/）は WordPress で運営する地域メディアで、複数のライターが記事（投稿）を書いている。2026-11-03 時点で公開記事は 225 本、公開記事のある著者は 21 人（うち 1 人が 53%）。最初の記事は 2025-08-28、定常的な投稿は 2025-10 から。直近 12 か月の月間公開本数は 11〜28 本。
- アクセスの計測は GA4（gtag.js、測定 ID G-79CFGF83VT）だけで、WordPress 側の統計プラグイン（Jetpack Stats、WP Statistics など）は導入されていない。ただし Analytify プラグイン（GA4 の数字を WordPress 管理画面に表示する）が入っており、運営者はこれで GA4 の数字を見てきた可能性がある（見てきた数字が表示回数かユーザー数かは Q-32）。
- GA4 の管理画面は、権限の付与が要り、記事・著者・カテゴリの軸で見るには設定や操作の習熟が要る。運営者とライターが、ログインなしで、自分たちの言葉（記事、ライター、カテゴリ、シリーズ）で数値を見られる場が欲しい。
- 本プロジェクトは、GA4 と WP REST API の集計値を日次で取り込み、Web の BI として公開するもの。工程は要件定義 → 設計 → 構築 → デプロイで、本文書群は要件定義の成果物。

## 2. 目的

1. 運営者が、サイト全体の傾向（読まれた回数を主指標に、補助として訪問回数と読んだ人の数、流入元、デバイス、地域、曜日×時間帯）を期間比較つきで把握し、編集方針（力を入れるカテゴリ、SNS の使い方、過去記事の再紹介）を決められる。
2. ライターが、自分の記事の反応（公開後の立ち上がり、流入元、長く読まれている記事の再浮上、節目への到達）を、全記事の分布（3 つの帯）と自分の過去の記事と比べて見られ、次の記事のテーマや書き方、次に紹介する場所に活かせる。ライター同士を競わせない（順位表を作らない）。
3. どちらもログインなしで見られる。そのために、個人情報とセキュリティ上まずい情報は一切出さず、「見られても責められない形」で数字を見せる（NFR-94〜NFR-99）。
4. 投稿活動（本数、カテゴリ構成）は GA4 に依存せず、WP REST API だけで先に見られる。

## 3. スコープ

### 3.1 やること

- GA4 Data API から日別の集計値を取り込む（DS-01、M-01〜M-03、M-06、M-09〜M-17）。
- WP REST API（wp/v2 のみ）から記事・著者（表示名と著者ページ URL）・カテゴリ・タグのメタデータを取り込む（DS-02、M-26、M-30〜M-34）。
- 両者を記事 ID で結合し、記事の立ち上がり曲線、全記事の中央値・四分位（3 つの帯）、到達のお知らせ、自分の過去との比較、過去の記事が今も読まれた回数、「普通の記事」の帯を計算する（M-18〜M-27）。
- 集計値を Supabase に格納し、Vercel 上の BI から読んで表示する。画面は 6 種（全体ダッシュボード、記事一覧とランキング、ライター別、カテゴリ・タグ別、投稿活動、反応指標）。要件は 04_functional.md。
- 小さな数を格納時に伏せる（T = 5）、非公開記事を除外する、著者は表示名と著者ページ URL だけ、順位表を出さない、などの公開データの規則を要件（NFR-30〜NFR-39）として定める。
- 表示と言葉の規則（1 画面 1 つの問い、比較の相手を添える、個人の数字に良し悪しの色を使わない、既定の期間は直近 28 日、スマホでは表は 4 列程度、説明文を画面に埋め込む）を要件（NFR-94〜NFR-99）として定める。
- 日次バッチの失敗通知と初回のバックフィル（FR-70〜FR-76）。

### 3.2 やらないこと

- リアルタイムの値、個別ユーザーの追跡、IP アドレス・ユーザー ID・完全な参照 URL・サイト内検索語・フォーム送信内容の取得と表示（NFR-32）。
- ログイン機能、利用者ごとの権限、BI 上での設定変更 UI（NFR-20、NFR-22）。
- 対象サイト（WordPress）の設定変更。GA4 のイベント設定や Search Console の登録が必要な場合は依頼者に依頼する。
- 問い合わせフォームの送信数・内容（FR-63、M-43）。
- ライター同士の順位表と、著者を数値で並べ替えられる表（FR-35 は廃止、NFR-36）。有効化の設定も持たない。
- ライターの非表示の申し出に対応する除外の仕組み（FR-36。2026-11-04、依頼者の決定。申し出があったときに検討する）。
- コメント件数（M-42、FR-62、DS-07 は廃止）。対象サイトでコメント機能が使われていないため（公開コメント 0 件、comment_status は closed）。
- いいね数（M-40、FR-60）。現状は取得不可で、出すならサイト側の変更が必要（Q-10 の 1）。
- エンゲージメント率、直帰率、平均セッション時間（M-05、M-07、M-08 は廃止）。利用者に説明できず、誤読の害があるため。
- イベント日を基準にした読まれ方の集計。イベント記事の開催日は本文中の文章にしかなく、構造化されたフィールドがないため現状では作れない。将来、サイト側で開催日のフィールドが用意されれば候補になる。
- Search Console の検索クエリ（M-50）。初回スコープ外（仮、Q-09）。将来出す場合も記事別の表示回数・クリック数だけで、検索語は出さない。
- サーバーログの取り込み（DS-03。仮、Q-21。ホスティングは Xserver と確認済み、ログの取得可否は未確認）。
- 広告効果の収益換算、将来予測、異常検知の通知。
- 週次・月次の定期配信（メール、LINE など）。要否は Q-24。
- Universal Analytics 時代のデータの取り込み。
- 技術選定（フレームワーク、ライブラリ）。設計工程で行う。

## 4. 前提（確認済みの事実）

2026-11-03 に親エージェントが確認した事実票に基づく。

- 対象サイトは WordPress 7.1.4、テーマ Snow Monkey、子テーマ takatsuconnect。
- 計測は GA4 の gtag.js のみ（測定 ID G-79CFGF83VT）。Jetpack Stats、WP Statistics、Matomo、Site Kit はトップページから検出されない。
- 主なプラグイン: snow-monkey-blocks、snow-monkey-forms、wp-ulike（いいね）、add-to-any（シェアボタン）、spotlight-social-photo-feeds、official-facebook-pixel。
- WP REST API（/wp-json/wp/v2/）は公開。posts、categories、tags、users/<id>（個別）が取れる。users 一覧は無効化されている。記事 URL は https://takatsu-connect.com/<記事 ID>/。takatsu/v1、tc/v1、takatsu-bot/v1、mcp、members/v1、wp-ulike/v1、wp-analytify/v1 などの名前空間もあるが、本 BI が使うのは wp/v2 だけ。
- 公開記事は 225 本（2026-11-03）。公開記事のある著者は 21 人。うち 1 人（表示名 SBC）が 120 本（53%）。次いで 19、17、11、8、6 本。3 本以下の著者が 11 人。表示名 SBC の著者が運営者本人かは未確認（Q-31）。文書では著者を WordPress のユーザー ID で書かず、表示名だけで書く（NFR-35 の趣旨。監査 L-2）。
- カテゴリは二階層（親: イベント、記事、マップ、広告）で、同名の子が別の親の下にある。225 本のうち 198 本（88%）が複数カテゴリに属し、多くは「記事」の木と「イベント」の木の両方に子を持つ。「イベント」の木に属する記事は 127 本。タグはシリーズ企画を束ねている。
- コメント: 公開コメントは 0 件、確認した記事の comment_status は closed。コメント機能は使われていない。
- wp-ulike: いいねボタンは記事ページにあるが、REST API（wp-ulike/v1）には templates のルートしかなく、いいね数は取れない。GA4 イベントも送っていない（記事 HTML の gtag は config だけ）。
- add-to-any: シェアボタンはある。a2a_config に計測の設定はないが、GA4 には `AddToAnyShare` というイベント名で届いている（直近 90 日で 36 件。2026-11-03 確認、D-09）。サービス別は GA4 Data API から取れない（D-09 確認済み）。シェア数は初回対象外（FR-61）。
- Analytify プラグイン（wp-analytify/v1）が入っている。
- 記事の meta に露出しているのは _tc_wrapper、footnotes、wp-seo-meta-description、wp-seo-meta-robots のみ。イベント記事の開催日は本文中の「開催日時」の文章にしかなく、構造化されたフィールドはない。
- ホスティングは Xserver（sv16640.xserver.jp、nginx）。アクセスログの取得可否は未確認。
- GA4 プロパティのプロパティ ID は依頼者が控えている。サービスアカウントに閲覧者権限を付与済み。認証は Workload Identity Federation（鍵なし）。
- GA4 の日次データは処理に通常 12 時間、24〜48 時間かかることがあり、遅延データは最大 7 日。日次データはプロパティのタイムゾーンで 15:30 に揃う。
- GA4 プロパティ（2026-11-03 に依頼者が GA4 Admin API と Data API を読み取り専用で実行して確認。Q-05、Q-07、Q-25 回答済み）: プロパティ名「高津コネクト ウェブサイト」。タイムゾーン Asia/Tokyo、通貨 JPY、サービスレベルは標準（GA4 Standard）。作成は 2025-10-07（JST では 10 月 8 日未明）で、GA4 の導入は 2025-10。Data API で取得できる最古の日は 2025-10-08。Universal Analytics 時代のデータはない。Web データストリームは 1 つ（測定 ID G-79CFGF83VT）。
- GA4 のデータ保持: イベントデータ 2 か月、ユーザーデータ 14 か月（新しいアクティビティでリセット有効）。Data API の集計レポートには影響せず、2025-10 からの値が取れることを実測で確認した。
- GA4 のカスタム次元と拡張計測: サイト側が設定したカスタム次元はイベントスコープの `page_type`（投稿 post か、そうでない other か）1 つ。残り 10 個は Analytify プラグインが作ったもので、本 BI では使わない。著者・カテゴリのカスタム次元とカスタム指標はない（記事との結合は pagePath の記事 ID で行う）。拡張計測はすべて有効で、scroll（90% 到達）イベントが届いている（M-09 に使える）。
- GA4 のイベント名（直近 90 日）: page_view 13,753、scroll 2,721、AddToAnyShare 36 ほか。form_start / form_submit、view_search_results、file_download、click も存在するが、本 BI では取得しない（NFR-32、FR-63）。
- 規模（2026-11-03 確認）: 月別の読まれた回数（表示回数）は 2025-10〜2026-10 でおおむね月 3,000〜7,700 回、直近 3 か月は 3,700〜4,500 回。2025-11 の値（1,274）は他の月と不連続。直近 90 日の訪問回数はスマホ 77%、パソコン 22%、タブレット 2%。流入は検索 66%、直接 20%、SNS 10%（SNS はほぼ Instagram と Facebook）。国内の市別では川崎市がおおよそ 3 分の 1。地域の粒度は市までで、川崎市の区（高津区）は出ない（Q-11 回答済み）。この規模で伏せ値 T = 5 と M-22 の下限 20 を維持する（D-11）。
- 未確認（その他）: API の割当（D-01）、Search Console の利用（Q-09）、アクセスログの取得可否（Q-21）。

## 5. 制約（依頼者の決定、2026-11-03）

技術選定ではなく、要件を満たすうえでの制約として扱う。

- 利用者は運営者と高津コネクトのライター。ライターは「自分の記事がどうか」と「全体としてどうか」を見る。
- ログイン機能は持たせず、誰でも見られる。したがってセキュリティ上まずい情報と個人情報は出さない。
- 全体構成は 2 つに分ける。(1) 情報を取得して Supabase に格納する仕組み。日に 1 度、GitHub Actions で実行し、Web サービスとしては公開しない。(2) Supabase から読む BI。Vercel で動かし、Supabase はブラウザからではなく Vercel のサーバー側から読む。
- リポジトリは public。秘密情報はリポジトリに置かない。
- 公開してよいデータの規則は .claude/rules/security.md が正。要件では NFR-30〜NFR-39 として ID を付けた。ライター同士の順位表は出さず、有効化する設定も持たない（NFR-36）。
- analytics-advisor の助言（advice/2026-11-03-metrics-review.md）は 2026-11-03 に全採用した。主指標は表示回数 1 つ（「読まれた回数」）、比較の相手は全記事の分布（3 つの帯）と自分の過去に限る、見せ方の規則は NFR-94〜NFR-99。
- 技術選定は設計工程で行う。
