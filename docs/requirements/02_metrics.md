## 1. 「アクセス数」の定義

- 確定（2026-11-03、Q-01）: 「アクセス数」= 表示回数（GA4 の screenPageViews）。画面では「読まれた回数」と呼び、PV は括弧で添える（例: 読まれた回数（PV））。主指標はこれ 1 つ。
- 訪問回数（セッション、M-02）と読んだ人の数（ユーザー、M-03）は全体ダッシュボードの補助指標に限り、記事・著者の画面には出さない。理由: 似た数を 3 つ並べると「どれが本当のアクセス数か」で迷う。表示回数は日・記事・著者・カテゴリで足せるので、どの画面でも同じ値が出て説明が一致する。ユーザー数は足せないので主指標にすると画面ごとに値が食い違う。
- 運営者がこれまで WordPress 管理画面（Analytify）や GA4 で「ユーザー数」を見てきた場合、切り替え時に「以前の数字より大きく出ます」と一度説明する（Q-32）。
- 用語の対応と画面での名称は docs/glossary.md §1 にまとめる。各指標の「画面での名称」は §4 の表に添える。

## 2. 共通の規則（粒度・比較・期間・表示）

- 粒度: GA4 由来の指標のうち日単位で格納するのは 05_non_functional.md §4.1 の表の範囲（全体 × 日の読まれた回数・訪問回数、全体 × 日 × 流入チャネル / デバイス、記事 × 日の読まれた回数）だけで、週・月・任意の期間はそこから集計する。記事 × 内訳軸（流入チャネル、SNS 種別、デバイス）と、全体 × 高カーディナリティ次元（SNS 種別、曜日 × 時間帯、初めて / また来た）は日単位では格納せず、公開する期間（直近 7 / 28 / 90 日、月、各前期間）ごとに集計してから伏せ値を適用して格納する（2026-11-03 変更、監査 H-1）。識別性の高い次元（参照元ドメイン M-12、地域の市 M-14）は移動窓（直近 7 / 28 / 90 日）では公開せず、全体は確定した暦月（前月以前）の値、記事（M-12 の上位 3）は公開後 30 日時点の値だけを格納・公開する。画面では期間の選択に連動せず、その旨を注記する（FR-01、FR-13、FR-15、FR-23。05 §4.1 の用語と線引き。2026-11-03 変更、再確認 N-2）。ユーザー数（M-03、M-15）は日別の値を足しても期間のユニーク数にならないため、期間単位で別途取得する（D-06）。
- 期間: 直近 7 日、直近 28 日、直近 90 日、月別（FR-01）。既定は直近 28 日（NFR-98）。「直近」は基準日（前日、NFR-02）を終端とする。
- 比較: 直近 N 日は「その前の N 日」と比較する。月別は「前月」と「前年同月」と比較する。比較値は差と比率（%）の両方を出すが、比率と変化率は分母が 20 未満のとき出さず、差の数だけ出す（NFR-33、NFR-96）。前年のデータがないときは「前年のデータなし」と表示する。
- 表示の言葉: 画面では GA4 の指標名を使わず、§4 の「画面での名称」と docs/glossary.md §1 の言葉を使う。個人（記事・著者）の数字に良し悪しの色を付けない（NFR-94〜NFR-99）。
- タイムゾーン: 確定（2026-11-03、Q-07）。日付の切り方は GA4 プロパティのタイムゾーン Asia/Tokyo。WordPress の公開日時はサイトのタイムゾーン（REST API の date）で、同じ JST であることを前提にする（違えば設計で変換する）。GA4 側の変換は不要。
- 確定: GA4 の日次データは確定まで 24〜48 時間、遅延データは最大 7 日。直近 7 日の値は再取得で変わり得る（FR-71）。BI には「直近 2〜3 日の数字はあとで増えることがあります」と注記する（FR-02）。
- 伏せ値: 確定（2026-11-03、Q-02）。しきい値 T = 5。細かい次元で切った集計値が 5 未満のときは格納時に伏せ、表示は「—」とし、セルの近くに「伏せ値」と添える（NFR-33、FR-73）。二次伏せしたセルも同じ表示にし、一次・二次を画面で区別しない。説明文（NFR-99）には「5 回未満の小さな数と、小さな数が分かってしまう隣の数は表示していません」と書く（2026-11-03 変更、Q-33。同日の画面レビューで「合計から逆算できてしまう隣の数」を平易な言い方に改めた）。格納する組み合わせ・粒度・伏せ値の適用は 05_non_functional.md §4.1 の表に従う（記事 × 内訳軸 1 つまで。記事 × 地域、記事 × 曜日 × 時間帯、内訳軸 2 つ以上、記事 × 日 × 内訳軸 は格納しない。「軸」の数え方は 05 §4.1 の用語）。排他的な区分（流入チャネル、SNS 種別、デバイス、初めて / また来た）では、伏せたセルが 1 つだけのとき、伏せていないセルのうち値が T 以上で最小のセルも伏せる（二次伏せ。NFR-33、再確認 N-1、設計レビュー M-1）。記事 × 日の読まれた回数は伏せ値の対象外（M-18 の累積から復元できるため。監査 M-2 (a)）。伏せた値は合計にも使わない（合計と累積は伏せる前の値から計算して格納する。伏せずに格納する合計・累積は 05 §4.1 に列挙）。GA4 が行を返さない区分は 0 として格納し、伏せない（0 は個人に結び付かない）。二次伏せで追加して伏せるセルは、伏せていないセルのうち値が T 以上で最小のもので、該当がなければ追加しない（NFR-33、D-16 確定。2026-11-03 追加、設計レビュー M-1）。著者 × 内訳軸（M-10、M-11 の著者次元）は、同じ区分で伏せた記事のセルが 1 本だけのとき著者のセルも伏せる（NFR-33。2026-11-03 追加、設計レビュー M-2）。
- 記事の範囲: WP REST API が公開している投稿（publish）だけが「記事」。パスワード付きの投稿（status は publish のまま content.protected = true で返る）は含めない（NFR-34、FR-72。2026-11-03 時点で該当 0 本、D-13）。非公開化・削除・パスワード付きになった記事は次のバッチで BI から消す（NFR-34）。
- 広告カテゴリ: 確定（2026-11-03、Q-08）。全体の合計には含める。記事ランキング（FR-20、FR-22）と中央値の母集団（M-19、M-27）からは除く。カテゴリ別（M-32、FR-40）では別枠で出す。
- 母集団の下限: 中央値・四分位の計算に使う母集団は 30 本以上。未満なら範囲を広げるか「まだ比較できません」と出す（M-19）。
- 比較の相手: 記事・著者の数字の比較の相手は「前の期間」「全記事の分布（3 つの帯）」「その著者自身の過去の記事」の 3 つに限る（.claude/rules/security.md「公開するデータ」。2026-11-03 修正、再確認 N-6）。著者同士の比較（順位）は作らない（NFR-36）。
- 記事の値から合算する指標とサイト全体の値: 記事の値から合算する指標（著者、カテゴリ（親・子とも）、タグ、鮮度区分の合計と記事数、1 本あたりの中央値。M-23〜M-27、M-32、M-33、M-34 と、著者次元の M-10・M-11）は、すべての公開記事の値で出す（広告カテゴリの扱いは M-19、M-32、FR-40 に従う）。GA4 からサイト全体として直接取る値（M-01〜M-03、M-06、M-10〜M-16 の全体次元）とは、記事以外のページの分だけ一致しない（2026-11-04 変更）。

## 3. 記事と GA4 データの対応

- 記事の URL は https://takatsu-connect.com/<記事 ID>/ の形。GA4 の pagePath は「/<記事 ID>/」になるので、pagePath から記事 ID を取り出して WP REST API の記事（id）と突き合わせる。
- 表記ゆれ（末尾スラッシュなし、/?p=<ID>、大文字小文字）の正規化規則は設計で決める（D-05）。
- 記事 ID に対応しない pagePath（トップページ「/」、カテゴリ一覧、タグ一覧、著者ページ /author/<slug>/、固定ページ、検索結果、404）は「記事以外のページ」としてまとめる。全体の数値（M-01〜M-03、M-06 のサイト全体）には含め、記事単位の指標（ランキング、立ち上がり）には含めない。固定ページを個別に出すかは Q-17。
- 記事の属性（タイトル、著者、カテゴリ、タグ、公開日）は WP REST API から取り、GA4 の pageTitle は使わない（タイトルの変更や付加文字列でぶれるため）。
- 記事が削除されて pagePath だけが GA4 に残る場合は「記事以外」に含めず、「削除済み記事」として集計から除く（NFR-34）。
- イベント記事の開催日は本文中の文章にしかなく、構造化されたフィールドはない（2026-11-03 確認）。イベント日を基準にした集計は現状では作れない（00_overview.md §3.2）。
