# 02 指標定義

- 状態: 草案
- 更新日: 2026-11-03

## 1. 「アクセス数」の定義

- 運営者・ライターが使う「アクセス数」が、表示回数・セッション・ユーザーのどれを指すかは未確定（Q-01）。
- 仮: 「アクセス数」= 表示回数（GA4 の screenPageViews）とし、BI では「PV」と表記する。セッション数とユーザー数は補助指標として併記する。
- 用語の対応は docs/glossary.md §1 にまとめる。

## 2. 共通の規則（粒度・比較・期間）

- 粒度: GA4 由来の指標は日単位で格納し、週・月・任意の期間はそこから集計する。ただしユーザー数（M-03、M-04、M-15）は日別の値を足しても期間のユニーク数にならないため、期間ごとの値が必要なら期間単位で別途取得する（D-06）。
- 期間: 直近 7 日、直近 28 日、直近 90 日、月別（FR-01）。「直近」は基準日（前日、NFR-02）を終端とする。
- 比較: 直近 N 日は「その前の N 日」と比較する。月別は「前月」と「前年同月」と比較する。比較値は差と比率（%）の両方を出す。
- タイムゾーン: 日付の切り方は GA4 プロパティのタイムゾーン（Asia/Tokyo と想定、Q-07）。WordPress の公開日時はサイトのタイムゾーン（REST API の date）。両者が同じであることを前提にし、違えば設計で変換する。
- 確定: GA4 の日次データは確定まで 24〜48 時間、遅延データは最大 7 日。直近 7 日の値は再取得で変わり得る（FR-71）。BI には「直近数日の値は変わることがある」と注記する（FR-02）。
- 伏せ値: 細かい次元で切った小さな値は格納時に伏せる（NFR-33）。伏せた値は合計にも使わない（合計は伏せる前の値から別に計算して格納する）。
- 記事の範囲: WP REST API が公開している投稿（publish）だけが「記事」。非公開化・削除された記事は次のバッチで BI から消す（NFR-34）。

## 3. 記事と GA4 データの対応

- 記事の URL は https://takatsu-connect.com/<記事 ID>/ の形。GA4 の pagePath は「/<記事 ID>/」になるので、pagePath から記事 ID を取り出して WP REST API の記事（id）と突き合わせる。
- 表記ゆれ（末尾スラッシュなし、/?p=<ID>、大文字小文字）の正規化規則は設計で決める（D-05）。
- 記事 ID に対応しない pagePath（トップページ「/」、カテゴリ一覧、タグ一覧、著者ページ /author/<slug>/、固定ページ、検索結果、404）は「記事以外」としてまとめる。全体の数値（M-01〜M-09 のサイト全体）には含め、記事単位の指標（ランキング、立ち上がり）には含めない。固定ページを個別に出すかは Q-17。
- 記事の属性（タイトル、著者、カテゴリ、タグ、公開日）は WP REST API から取り、GA4 の pageTitle は使わない（タイトルの変更や付加文字列でぶれるため）。
- 記事が削除されて pagePath だけが GA4 に残る場合は「記事以外」に含めず、「削除済み記事」として集計から除く（NFR-34）。

各表の列: ID、名称、定義、計算式、粒度、ディメンション（切れる軸）、比較、出典（データソースと API 名）。出典の DS-xx は 03_data_sources.md を参照。

### 4.3 記事の立ち上がりと比較（M-18〜M-22）

| ID | 名称 | 定義 | 計算式 | 粒度 | ディメンション | 比較 | 出典 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M-18 | 公開後 N 日間の累積表示回数 | 記事を公開した日を 1 日目として、N 日目までの表示回数の累積 | Σ M-01(記事, d)、d = 公開日 … 公開日 + N − 1。N = 1 … 90 | 記事×経過日数 | 記事、著者、カテゴリ | M-19 との比較 | 派生（DS-01 + DS-02） |
