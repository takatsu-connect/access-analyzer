## 4. 公開してよいデータの規則（NFR-30〜NFR-39）

原本: .claude/rules/security.md「公開するデータ」。docs/security/audits/2026-11-03-initial.md の指摘（要件で ID を付けること）に対応する。

| ID | 要件 | 仮置き / 未確定 |
| --- | --- | --- |
| NFR-30 | 公開するのは集計値だけ。個別の訪問、個別のユーザー、個別のイベントの行は格納も表示もしない | ― |
| NFR-31 | 集計値を切る次元は次に限る: 記事、著者の表示名、カテゴリ、タグ、日付（日・曜日・時間帯を含む）、デバイス種別、流入チャネル、参照元ドメイン、地域（都道府県と市区まで）。この一覧にない次元を足すときは、要件に ID を付けて追加し、security-auditor のレビューを受ける（NFR-39） | ― |
| NFR-32 | 次のものは取得も格納も表示もしない: ユーザー ID、クライアント ID、完全な参照 URL、サイト内検索語、フォームの送信内容（問い合わせ送信数を含む、FR-63）、IP アドレス、市区より細かい地域、リアルタイムの値 | ― |
| NFR-33 | 細かい次元で切った集計値がしきい値 T = 5 未満のとき、格納時に「5 未満」を示す値に置き換える（伏せ値）。表示は「5 回未満」。読み出し側で丸めて済ませない。格納する組み合わせは「記事 × 内訳軸 1 つまで」に限る（記事 × 日、記事 × 流入チャネル、記事 × デバイスは格納する。記事 × 地域、および記事 × 地域 × デバイスのような 2 軸以上は格納しない。個人の推測が可能になるのは数の小ささより軸の細かさのため）。合計値と累積値（M-18）は伏せる前の値から別に計算して格納する。比率と変化率は分母が 20 未満のとき出さず、差の数だけ出す（公開性ではなく誤読の防止。NFR-96 と同じ）。T は設定値として外に出し、変更はコミットで記録する | 確定（2026-11-03、Q-02）。T = 5 |
| NFR-34 | BI に含める記事は、WP REST API が公開している公開状態（publish）の投稿だけ。非公開、下書き、パスワード付きは含めない。削除・非公開化された記事は次のバッチで、関連する集計値とともに BI から消す（FR-72） | ― |
| NFR-35 | 著者について格納・表示するのは、サイトが公開している表示名と著者ページの URL（slug）だけ。メール、ログイン名、WordPress のユーザー ID は格納しない（ユーザー ID は取り込み時の結合にだけ使う）。アバター画像を使うかは未確定 | 仮: アバターは使わない |
| NFR-36 | ライター同士の順位表（著者を数値で並べた表）は出さない。有効化する設定も持たない（公開 BI では「運営が見る」と「全員が見る」が同じになる。FR-35 は廃止）。著者を数値で並べ替えられる表も作らない。記事・著者の数字の比較は、全体の分布（中央値、四分位の 3 つの帯。FR-21、FR-23、FR-31）と、その著者自身の過去の記事（M-24）に限る。著者別の公開本数（FR-51）は名前順・順位の数字なし・並べ替えなしで出す。どの一覧にも順位の数字を付けない。2026-11-03 変更 | 確定（2026-11-03、Q-03） |
| NFR-37 | 地域の粒度は都道府県と市区まで。GA4 の city が市のレベルのため、実際には市まで。区以下は出さない | Q-11 |
| NFR-38 | 流入元は、流入チャネル（5 区分）と参照元ドメイン（sessionSource）まで。完全な参照 URL（pageReferrer）は取得しない | ― |
| NFR-39 | NFR-31 の次元、NFR-32 の除外、NFR-33 のしきい値を変えるときは、要件を更新し、ADR に理由を書き、security-auditor のレビューを受けてから実装する | ― |

## 11. 表示と言葉の規則（NFR-94〜NFR-99）

2026-11-03 追加。analytics-advisor の助言（advice/2026-11-03-metrics-review.md §2、§5、§6）の「見せ方」の規則に ID を付けたもの。設計（docs/design/05_screens.md）と画面に埋め込む説明文はここを参照する。前提: ログインがないので、ライター本人のページを他のライター・読者・運営が同時に見る。「見られても責められない形」を狙う。

| ID | 要件 | 仮置き / 未確定 |
| --- | --- | --- |
| NFR-94 | 1 画面 1 つの問い。各画面の見出しは利用者の問いの形で書く（例: 「この期間、サイト全体はどれくらい読まれた？」「この記事は普通より読まれた？」「読者はどこから来たか」「いつ読まれているか」「どんな記事が多かった？」）。1 つの画面に答えの違う問いを混ぜない | ― |
| NFR-95 | 数字には比較の相手を添える。比較の相手は、前の期間（「前の 28 日と比べて」「去年の同じ月と比べて」）、全記事の分布（「多くの記事はこの範囲」の 3 つの帯）、その著者自身の過去（M-24）のいずれか。著者同士の比較は作らない（NFR-36） | ― |
| NFR-96 | 比率（%）と変化率は、分母が 20 未満のとき出さず、差の数だけ出す（「+200%」が 3 → 9 で出るのを防ぐ）。伏せ値は「5 回未満」と表示する（NFR-33）。小さな数でも「少ない」とは書かない | ― |
| NFR-97 | 個人（記事・著者）の数字に良し悪しの色（赤・緑など）を使わない。帯の中の位置は 1 色の濃淡で示し、文言は中立の 3 区分（「よく読まれています」「多くの記事と同じくらい」「これから」）にする。前期間比の矢印の色も中立。地域の割合や流入元の構成は「性格」「傾向」として見せ、良し悪しの評価語を付けない。「偏り」「下位」「読まれなかった」など責める語を使わない | 文言は Q-29（ライター 2〜3 人に下書きを見せる） |
| NFR-98 | 既定の期間は直近 28 日（FR-01）。既定の並びは公開日順（FR-21、FR-24）。帯や数値で並べ替えられるのは、本人の記事同士（FR-32）と、上位だけが出る一覧（FR-20、FR-22、FR-24 の降順）に限る | ― |
| NFR-99 | スマートフォンでは表は 4 列程度（例: タイトル・公開日・読まれた回数・30 日 PV）、曜日×時間帯のヒートマップは時間帯を 6 区分に畳む（NFR-81）。説明文は別ページにせず画面に埋め込む: 各指標の 1 文の注記（glossary §1「添える注記」）、母集団の定義、伏せ値の意味、データの確定（FR-02）、「一部の記事は本人の希望により個別には表示していません」（FR-36）。画面の言葉は 02_metrics.md の「画面での名称」と glossary §1 に従い、GA4 の指標名は括弧でのみ添える | スマホ利用の実態は Q-27 |
