## 指摘

### 高

**H-1 伏せ値の許可リスト（NFR-33）が機能要件・指標定義と食い違い、格納粒度が未定義**
- 対象: NFR-33、FR-73、02_metrics.md §2、M-11・M-12・M-17（粒度「日」）、FR-23 (6)
- 問題: NFR-33 が格納を許す組み合わせは「記事 × 日、記事 × 流入チャネル、記事 × デバイス」の 3 つだが、FR-23 (6) と M-11・M-12・M-17 は「記事 × SNS 種別」「記事 × 参照元ドメイン（上位 3）」を求める。また 02 §2 と M-17 は GA4 由来の値を「日単位で格納」とするため、記事 × 流入チャネル等を日単位で持てば「記事 × 日 × 内訳軸」の 2 軸格納となり NFR-33 に反する。さらに「合計値は伏せる前の値から計算」の「合計」がどの単位（記事の期間合計か、期間内の記事 × チャネル値も含むのか）を指すか定義がない。
- 悪用の筋道: 設計が 02 §2 に従って日次格納を選ぶと、「ある日、記事 X に example-company.jp から 2 セッション」のような、特定の人の共有行動に結び付く小さな値が格納される。表示側で期間値を「合計」として生値から作れば、伏せ値も効かない。
- 影響: 訪問者のプライバシー。線引きの中核規則が無効になる。
- 対策（NFR-33 を次の形に直す）: (a) 許可する組み合わせを FR-23 に合わせて列挙（記事 × 日、記事 × 流入チャネル、記事 × SNS 種別、記事 × 参照元ドメイン、記事 × デバイス）。(b) 記事 × 内訳軸（日以外）は日単位で格納せず、公開する期間（直近 7/28/90 日、月、各前期間）ごとに集計してから伏せて格納すると明記。(c) 伏せずに格納する合計・累積を列挙（記事の期間合計、M-18、全体・カテゴリ・タグ・著者の合計）し、それ以外の内訳セルはすべて伏せ値の対象とする。(d) 記事以外の高カーディナリティ次元（全体 × 参照元ドメイン上位 10、市別上位 10、カテゴリ × 曜日 × 時間帯）にも T を適用するか明記する。参照元ドメインは個人サイトや組織のホスト名を含みうるため適用を推奨。
- 根拠: NFR-33 本文、02 §2「GA4 由来の指標は日単位で格納」、M-17 の粒度欄、FR-23 (6)。
- 関係: NFR-33、NFR-39、FR-73、FR-23、M-11、M-12、M-17、D-08

**H-2 非表示著者（FR-36）の除外範囲に、URL 直接指定と記事詳細の穴**
- 対象: FR-36、FR-23、FR-06、FR-30、FR-42、M-22
- 問題: FR-36 の除外対象は一覧（FR-20〜22、FR-24、FR-34、FR-51）とライター別ビューだが、(a) 記事詳細 FR-23 が挙がっていない。記事 ID はサイト上で公開されており（URL が /<ID>/、4800 前後）、FR-06 の URL に ID を入れれば一覧に出ない記事の詳細（著者名、PV、M-24 の著者中央値）が開ける。(b) FR-30 の「URL で著者を直接指定できる」について、除外著者の slug（公開済み）を指定したときの挙動が未定義。(c) FR-42 の「タグごとの記事一覧」は記事単位の一覧だが、FR-36 では合計側に分類されている。(d) M-22 の「全体で 10 件」の表示先 FR がなく、除外の対象にも入っていない。
- 悪用の筋道: 除外を一覧の問い合わせだけで実装し、詳細・URL 経路に適用し忘れる。
- 影響: 本人の申し出に反する個別表示。security.md「公開するデータ」13 行目の規則違反。
- 対策: FR-36 を「除外は画面ごとでなくデータ層で行う。個別表示用の公開ビュー（記事行・著者行）に除外著者の記事・著者を含めない。URL で直接指定されたときは存在しない記事・著者と同じ応答にする」と書き直し、FR-23、FR-42 の記事一覧、M-22 全体を除外対象に明記する。設計では D-10 とあわせてビューの定義として実装する。
- 根拠: FR-36 の対象列挙、FR-06・FR-30 の URL 指定、FR-42 本文、M-22 の表示件数欄。
- 関係: FR-36、FR-23、FR-06、FR-30、FR-42、M-22、NFR-22、NFR-52、D-10

### 中

**M-1 「誰が除外されたか分からない」は達成できない約束（FR-36、NFR-22）**
- 問題: 著者の集合はサイトの著者ページと WP REST API（posts の _embed）で公開されている。FR-30 の著者一覧や FR-51 の著者別一覧をサイトの著者と突き合わせれば、除外された著者は特定できる。FR-51 の主表示「◯人・◯本」（除外込み）と一覧の差分も同じ情報を与えるが、名前の突き合わせで足りるため、新たな推測の経路ではない。
- 影響: 要件が実現できない性質を約束し、申し出た本人の期待と食い違う。
- 対策: 許容する。文言を「画面に除外の表示を出さない」に改め、「サイトの著者一覧との突き合わせで推測されうる」ことを Q-30 の説明文面に含める。FR-51 の主表示は現状のままでよい（人数・本数ともサイトから分かる値）。あわせて、1 人の著者だけで構成されるタグ・子カテゴリの合計（FR-40、FR-42）がその著者の数値そのものになる点を要件に注記し、許容するか「著者 2 人以上のときだけ合計を出す」とするかを設計で決める。
- 関係: FR-36、FR-51、FR-30、FR-40、FR-42、NFR-22、Q-30

**M-2 記事 × 日の伏せ値は累積曲線と期間窓の差分から復元できる**
- 問題: M-18 は伏せる前の値から N = 1〜90 の累積を格納し、FR-23 (3) が曲線として表示する。cum(N) − cum(N−1) がその日の表示回数そのものなので、公開後 90 日間の記事 × 日の伏せ値は無意味になる。91 日目以降も、直近 7/28/90 日の記事合計（生値）を毎日取得すれば、差分から日別値に近い値を復元できる（公開 BI なので毎日の取得は妨げられない）。
- 問題になる粒度: 記事 × 日（公開後 90 日は完全に、以降は時間をかければ）。記事 × 流入チャネル等には累積がないため影響しない（H-1 の対策 (b) が前提）。
- 影響: 低〜中。記事 × 日の 1〜4 回は単独では個人の特定に直結しないが、規則が機能していない状態で公開することになる。
- 対策（いずれかを選び NFR-33 に書く）: (a) 記事 × 日は伏せ値の対象から外し、理由（累積から復元可、日別値だけでは個人に結び付かない）を ADR に書く。伏せ値は記事 × 内訳軸（日以外）に集中させる。(b) 伏せ値を保つなら、M-18 の公開粒度を粗くする（N = 1、3、7、14、30、60、90 など）か、累積の増分が T 未満の区間を曲線上で平らに描く。日次取得による復元は (b) でも残るため、(a) を推奨。
- 関係: NFR-33、M-18、M-20、FR-23、FR-01、FR-73、D-08

**M-3 パスワード付き記事を除く条件が要件にない（NFR-34、FR-72）**
- 問題: security.md 10 行目はパスワード付き記事を取り込まないと定めるが、NFR-34・FR-72 の条件は「公開状態（publish）」だけ。WordPress ではパスワード付き投稿も status は publish で、REST API には content.protected = true として返る（WordPress の一般仕様。対象サイトでの確認は依頼者に依頼）。
- 対策: NFR-34 と FR-72 に「content.protected が true の投稿（パスワード付き）は含めない。既に取り込んだ記事が後からパスワード付きになったら次のバッチで消す」を追加。
- 関係: NFR-34、FR-72、security.md 10 行目

**M-4 FR-24 の降順並べ替えは全記事の順位表になる**
- 問題: FR-24 は全記事を読まれた回数・7 日 PV・30 日 PV の降順で並べ替えられる。昇順を禁じても、降順の末尾が「最も読まれなかった記事と著者」になる。FR-20・FR-22 が上位 20 に絞っている意味が失われ、FR-05 の CSV で持ち出せる。NFR-98 はこれを「上位だけが出る一覧」と扱っているが、FR-24 は全件。
- 対策: FR-24 の数値による並べ替えは、著者またはカテゴリで絞ったときだけ有効にするか、降順でも表示件数を上位 N（例: 50）で止める。既定の公開日順はそのまま。
- 関係: FR-24、FR-05、NFR-36、NFR-98

**M-5 除外リストが「秘密情報」として分類されておらず、NFR-40〜44 の規則が及ばない**
- 問題: NFR-40〜44 の対象は鍵・トークン・パスワード。除外リスト（D-10）は環境変数か非公開テーブルに置くが、ログ・通知・コミットメッセージ・Issue・文書への記載禁止、.env.example、`NEXT_PUBLIC_` の禁止、anon からの不可視、キャッシュの更新が明文化されていない。beads の Issue はリモートに同期されるため、申し出た著者名を Issue に書くと公開範囲によっては露出する。
- 対策: NFR-40 に「非表示を申し出た著者の一覧は秘密情報として扱い、本節の規則をすべて適用する」を追加。NFR-43 に「除外リストの表は anon から select できず、公開ビューは除外を適用した行だけ返す。公開ビューに除外の有無を示す列を置かない」を追加。NFR-44 に「除外リストの内容と申し出た著者名」をログ・通知・Issue・コミットに書かない対象として追加。NFR-11 に「除外リストの変更後はキャッシュを再生成する」を追加。NFR-73 の運用記録は、著者名を含む台帳をリポジトリ外に置くと明記。
- 関係: NFR-40、NFR-43、NFR-44、NFR-11、NFR-73、NFR-22、D-10

**M-6 一般注記の出し方が除外の有無を示しうる（NFR-99、FR-36）**
- 問題: 「一部の記事は本人の希望により個別には表示していません」を、除外著者がいるときだけ、または特定の画面だけに出すと、注記の出現が除外の発生を知らせる。
- 対策: NFR-99 に「この注記は除外著者の有無にかかわらず常に、全画面共通の説明文に含める」と書く。
- 関係: NFR-99、FR-36、NFR-22
