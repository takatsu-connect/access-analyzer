## 結論

イベント記事のタブは、360px の 4 列 × 2 行でも押せる大きさ（82 × 44px）を保ち、はみ出しもなく、ほぼ問題ない。ただし、イベント記事の詳細を開くと現在地が「記事」になり、依頼者が重視する「記事とイベント記事は別」が詳細の画面で崩れている。S-06b の親ごとの分け方は、表（親の名前の行と縦の線）はよくできているが、図は親ごとに行の名前の幅が変わるため月の列がそろわず、360px では長い子カテゴリ名のある親の図がつぶれる。

最優先で直すことは次の 3 つ。

1. S-06b: 親ごとの図の行の名前の幅をページで 1 つにそろえ、月の列の位置を全親で同じにする（H-1）。
2. S-03: イベント記事の詳細では、ヘッダの現在地とサブナビを「イベント記事」にする（H-2）。
3. S-06b: 凡例と「マスをタップすると…」を全親で 1 回にし、親の見出しを決まりの h2 の大きさにする（M-1、M-2。(b)(c)）。

## 指摘

件数: 高 2、中 4、低 2。

### H-1 親ごとの図で月の列がそろわず、360px で図がつぶれる（S-06b、子カテゴリ）

- 画面と場所: `/categories/seasonal?axis=child` の親ごとの `Heatmap`（`SeasonalScreen.tsx` の `.group` ごと）。
- いまの状態: 行の名前の列の幅を図ごとに子カテゴリ名の長さで決めている。1280px で「イベント」の図のマスは x=238 から、「記事」の図は x=426 から始まり、同じ月が縦に並ばない（`seasonal-child-l-dark.png`）。360px では「記事」の図の名前の列が 250px を取り、マスは 3 列だけが見え、月の目盛りが「2025/12026/12026/」と重なって読めない（`seasonal-child-s-light.png` の中ほど）。架空データの名前は長い試験用の文字列だが、実際の子カテゴリにも長い名前は入りうる。
- 問題: 親をまたいで「同じ月にどこが濃いか」を目で追えない。360px では、2 つめ以降の親の図が「壊れている」ように見え、タップの的も小さくなる（マスの幅が約 26px）。
- 直す案:
  - 行の名前の幅を、全親の子カテゴリ名からページで 1 つ決め、各 `Heatmap` に同じ値を渡す。上限を設け（360px で 7em 前後、1280px で 12em 前後）、超える名前は `text-overflow: ellipsis` で切る（全文は同じ値の表と固定行にある）。
  - マスの幅は親の数や名前の長さにかかわらず同じにし、360px では 44px を下回らせない（`--tap-min`）。横スクロールは親ごとの枠の中に残るが、全親で同じ位置から始まるので、目盛りの位置がそろう。
  - あわせて、360px の初期の横位置を右端（最新の月）にそろえる。いまは選んでいるマス（2026/10）が画面の外にあり、固定行の文がどのマスを指すか見えない。
- 重要度: 高

### H-2 イベント記事の詳細で、ヘッダの現在地が「記事」になる（S-03）

- 画面と場所: `/articles/111`、`/articles/112`（カテゴリが「イベント」だけの記事）の `SiteHeader`。
- いまの状態: 主タブの現在地（地と下線）は「記事」、サブナビは「よく読まれた記事 / 新着記事の立ち上がり …」。`/events/top` の一覧から開いても同じ（`aria-current` を測定）。
- 問題: イベント記事の一覧から記事を開くと、現在地が別のタブへ飛ぶ。ライターは「記事」と「イベント記事」を別のものと意識している（依頼者）ので、「自分のイベント記事が記事扱いになった」と受け取りうる。サブナビを押すと記事のほうの一覧へ移り、戻り先も違う。
- 直す案: S-03 の現在地を、比べる相手と同じ決まり（`articles.ts` 253 行目の「記事に属せば記事、そうでなくイベントならイベント」。page-data の `benchmarkSection`）で決め、`SiteHeader` に渡す。`event` のときは主タブ「イベント記事」に `aria-current` を付け、サブナビもイベント記事の 5 つにする。URL は `/articles/[postId]` のままでよい。
- 重要度: 高

### M-1 凡例、操作の説明、固定行が親の数だけ繰り返される（S-06b。依頼の (b)）

- 画面と場所: 各 `.group` の中の `Heatmap` の下の「マスをタップすると、その月の数字に変わります」（`.hint`）、固定行（`.fixedRow`）、凡例。
- いまの状態: 親 2 つで、同じ説明と凡例が 2 回ずつ、固定行が 2 本出る。360px では 1 親あたり図の下に約 150px の文が続き、図より文のほうが長い（`seasonal-child-s-light.png`）。
- 問題: 同じ文を 2 度読ませ、親が増える（マップ、広告に子ができる）ほど画面が文で埋まる。固定行が 2 本同時に「2026 年 10 月 …」を出すので、どちらが自分のタップの結果か一瞬迷う。
- 直す案:
  - 凡例と `.hint` は、全親の上（軸の切り替えと「→ 横にスクロールできます」の下）に 1 回だけ置く。どの親の図にも同じ意味なので、繰り返す情報がない。
  - 固定行は親ごとに残す（タップしたマスのすぐ下に結果が出ることが大事で、360px で 1 本にまとめると図から遠くなる）。ただし初期状態は、最初の親だけに値を出し、2 つめ以降は空にせず、選んでいないことが分かる短い文にするか、最初の親以外は初期の文を出さない。文言は analytics-advisor に委ねる。
  - 固定行の文頭の「イベント >」は、親の見出しの直下では繰り返しになる。置き場所としては省いても迷わない（文言の判断は analytics-advisor）。
- 重要度: 中

### M-2 親の見出しが 16px で、共通の h2 の大きさと違う（S-06b。依頼の (c)）

- 画面と場所: `seasonal.module.css` の `.groupHeading`（`font-size: var(--font-size-md)`）。
- いまの状態: 360px、1280px とも 16px。同じ構造の `/categories` の親の h2（「マップ」「イベント」…）は 18px / 24px で、ページを行き来すると親の名前の重みが変わる。05 §2.9 は h2 を 18px（広い画面 24px）に固定している。
- 問題: h2 が本文と同じ大きさで、図の上の目盛り（12px）と行の名前（13〜14px）に対して段がはっきりしない。1280px では「記事」の見出しが左に寄り、図は x=426 から始まるので、見出しと図の結びつきも弱い（H-1 を直せば解消）。
- 直す案: `.groupHeading` の `font-size` の上書きを消し、共通の h2 の大きさ（18px / 24px）にする。h1 の 24px / 32px と比べて親の見出しが重すぎると感じるときでも、h3 にはしない（読み上げで h1 の直下の節になるのが正しい）。区切りは `.group + .group` の罫線（いまの 1px）と `--space-5` の間隔のままでよい。
- 重要度: 中

### M-3 親の並びがカテゴリの画面ごとに違い、設計の順でもない（S-06、S-06b。依頼の (a)）

- 画面と場所: `/categories/seasonal?axis=child` の図と表（イベント → 記事）、`/categories` の h2（マップ → イベント → 記事 → 広告）。
- いまの状態: S-06b は ID 順、S-06 も実測では「マップ」が先頭で、04 §3 の「記事 / イベント / マップ / 広告」と一致しない（依頼文では S-06 は設計どおりとあったが、ローカルのビルドではそうなっていない）。
- 問題: 2 つの画面を行き来すると、同じ親が違う位置にある。記事の本数と読まれた回数が多い「記事」が 2 番目に来て、最初に目に入るのが量の少ないイベントになる。新しい親カテゴリができたときに並びが ID で変わるのも、読む人には理由が分からない。
- 直す案: 親の並びを 04 §3 の順（記事、イベント、マップ、広告）でデータ層の 1 か所の定数にし、S-06、S-06b の図、S-06b の表の親の列のまとまり、S-08 の内訳で同じものを使う。決まっていない親は末尾に ID 順。並びは量の順ではなく固定の順なので、カテゴリを競わせる印象も生まない。
- 重要度: 中

### M-4 比べる相手の一言が、帯を描いているのに出ないことがある（S-03）

- 画面と場所: `CurveSection.tsx` 80〜82 行目。一言（`Notice`）は「帯の文」がないとき出さない。
- いまの状態: `/articles/101`、`111`、`112` では、図に「多くの記事はこの範囲」の帯と「真ん中の記事」の点線を描いているが、文は「まだ比較できません」で、比べる相手の一言が出ない（`art101-top-s.png`）。109 などでは、一言が帯の文と帯の中の位置の印（`BandDot`）の間に入る（`scope-109-s.png`）。
- 問題: いちばん読み違えやすいのは、帯が見えているのに比べられないイベント記事の場合で、そこで「この帯は誰の帯か」が分からない。また、帯の文と `BandDot` は同じ事実の言葉と図なのに、一言がその間に割り込み、つながりが切れる。
- 直す案: 一言の条件を「帯を描くとき」（帯のデータがあるとき）に変える。置き場所は図の凡例の直下、帯の文より前にし、帯の文と `BandDot` を続ける。大きさは `Notice` の 14px の薄い色のままでよい。
- 重要度: 中

### L-1 360px の主タブ「イベント記事」の幅の余裕が小さい（SiteHeader）

- 画面と場所: 360px の主タブ（4 列、各 82 × 44px、14px）。
- いまの状態: 「イベント記事」は 6 文字で 84px 前後あり、セルの幅（82px）とほぼ同じ。今は 1 行に収まっている（`events-top-top-s.png`）。2 行目の 4 列目は空いている。
- 問題: 端末の文字の拡大（110% 程度）で「イベント記 / 事」と折れるおそれがある。
- 直す案: `.link` の左右の padding を 360px で `var(--space-1)` 以下にし、`word-break: keep-all` を当てて単語の途中で折らない。折れるときは「イベント / 記事」で折れるよう、辞書側で `イベント<wbr>記事` 相当の区切りを検討（文言の担当と相談）。
- 重要度: 低

### L-2 イベント記事のサブナビの名前が記事のサブナビと違う形になっている（SiteHeader）

- 画面と場所: `/events/*` のサブナビ（よく読まれた / 新着の立ち上がり / 長く読まれている / 最近よく読まれている / 探す）と `/articles/*`（…記事 が付く）。
- いまの状態: 同じ 5 つの画面の対応なのに、末尾の「記事」の有無で長さが違う。
- 問題: 大きな問題ではないが、主タブが画面の上へ流れた後（スクロール後）は、サブナビだけで「どちらの一覧か」が分からない。h1 に「イベント記事」とあるので迷いは小さい。
- 直す案: いまのままでよい（360px の横スクロールの量が減る利点が大きい）。h1 の問いに「イベント記事」が必ず入ることを、辞書の決まりとして 05 §1 に書いておくとよい。
- 重要度: 低
