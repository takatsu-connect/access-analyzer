## 2. GA4 の用語

| 用語 | 意味 |
| --- | --- |
| GA4 | Google アナリティクス 4。対象サイトは gtag.js（測定 ID G-79CFGF83VT）で計測している |
| プロパティ | GA4 でサイトごとに作る計測の単位。Data API はプロパティ ID（数字）で指定する。ID はリポジトリに置かない |
| GA4 Data API | GA4 の集計値を取り出す API。本 BI の主なデータソース（DS-01） |
| 次元（ディメンション） | 集計を切る軸。date、pagePath、deviceCategory など |
| 指標（メトリクス） | 集計する値。screenPageViews、sessions など |
| pagePath | URL のパス部分（例: /4800/）。クエリ文字列を含まない。記事 ID との突き合わせに使う |
| エンゲージメント | 10 秒以上の滞在、2 ページ以上の閲覧、コンバージョンのいずれかがあること。本 BI ではこの言葉を画面に出さない |
| 拡張計測機能 | GA4 がスクロール（90% 到達）、外部リンクのクリック、サイト内検索、動画、ファイルダウンロード、ページ変更、フォームの操作を自動で計測する設定。対象サイトではすべて有効で、scroll イベントが届いていることを確認済み（2026-11-03、Q-25 回答済み） |
| イベント名（eventName） | GA4 が記録する行動の名前。本 BI で使うのは scroll（M-09）と AddToAnyShare（add-to-any のシェア。M-41、D-09）だけ。対象サイトで届いているイベント名は page_view、user_engagement、session_start、first_visit、scroll、click、form_start、form_submit、AddToAnyShare、view_search_results、file_download（2026-11-03 確認）。scroll と AddToAnyShare 以外は取得しない（NFR-32） |
| カスタム次元 | サイト側が GA4 に追加した独自の次元。対象サイトにはイベントスコープの page_type（投稿 post か、そうでない other か）がある。Analytify プラグインが作った 10 個は本 BI では使わない。著者・カテゴリのカスタム次元はなく、記事との結合は pagePath の記事 ID で行う（D-15） |
| チャネルグループ（sessionDefaultChannelGroup） | GA4 が流入経路を分類したもの。Organic Search、Direct、Organic Social、Referral、AI Assistant、Unassigned、Email、Organic Video など。本 BI では 検索 / SNS / 直接 / 他のサイトから / その他 の 5 区分に正規化する（M-10）。AI Assistant 以下は「その他」 |
| データの確定 | GA4 の日次データは処理に通常 12 時間、24〜48 時間かかることがあり、遅れて届くデータは最大 7 日。確定前は値が変わる |
| タイムゾーン | GA4 のレポートはプロパティに設定したタイムゾーンで日付を切る。対象プロパティは Asia/Tokyo（2026-11-03 確認、Q-07 回答済み）。日次データが揃う 15:30 も JST |
| Workload Identity Federation（WIF） | 鍵ファイルを使わずに GitHub Actions から Google の API を呼ぶための認証方式。サービスアカウントの JSON 鍵は作らない |

## 3. WordPress の用語

| 用語 | 意味 |
| --- | --- |
| 投稿（post） | ブログ記事。本 BI で「記事」と呼ぶもの。URL は https://takatsu-connect.com/<記事 ID>/。2026-11-03 時点で公開記事は 225 本 |
| 固定ページ（page） | 「高津コネクトについて」などの記事でないページ。集計に含めるかは Q-17 |
| 著者（author） | 投稿を書いた WordPress ユーザー。本 BI では「ライター」と同じ意味。保存・表示するのは表示名と著者ページ URL（slug）だけ。公開記事のある著者は 21 人 |
| 表示名 | 著者がサイト上で名乗っている名前。実名風とハンドルが混在する |
| カテゴリ | 記事の分類。二階層（親: イベント、記事、マップ、広告）。同名の子が別の親にあるため「親 > 子」のパスで表示する。88% の記事が複数カテゴリに属するため、親カテゴリを別々の軸として扱う（Q-15） |
| タグ | 記事を横断して束ねるラベル。シリーズ企画（例: 多摩川カレーグランプリ）に使われている |
| WP REST API | WordPress が公開する API。本 BI が使うのは /wp-json/wp/v2/ だけ（DS-02）。他の名前空間（takatsu/v1、wp-ulike/v1、wp-analytify/v1 など）は使わない |
| 公開状態 | publish（公開）だけが REST API に出る。下書き、非公開は出ないため BI にも入らない。パスワード付きは publish のまま content.protected = true で出るため、取り込み時に除く（NFR-34、FR-72） |
| コメント | 対象サイトでは使われていない（公開コメント 0 件、comment_status は closed）。M-42、FR-62、DS-07 は廃止 |
| wp-ulike | 「いいね」ボタンのプラグイン。いいね数は REST API からも GA4 からも現状は取れない（M-40） |
| add-to-any | SNS シェアボタンのプラグイン。GA4 に AddToAnyShare というイベント名で届いている（2026-11-03 確認。M-41、D-09） |
| Analytify | WordPress 管理画面で GA4 の数字を見るプラグイン（wp-analytify/v1）。運営者がこれまで見てきた数字の出所である可能性がある（Q-32）。本 BI は使わない |
| Xserver | 対象サイトのホスティング先（sv16640.xserver.jp、nginx）。アクセスログの取得可否は Q-21 |

## 4. この BI で使う用語

| 用語 | 意味 | 関係する ID |
| --- | --- | --- |
| 基準日 | BI に表示されているデータの最終日。通常は前日（D-1）。画面では「◯月◯日までのデータです」 | NFR-02、FR-02 |
| 前期間比 | 選んだ期間の直前の同じ長さの期間との比較。月別は前月と前年同月。画面では「前の 28 日と比べて」「去年の同じ月と比べて」。分母 20 未満では % を出さない | FR-01、NFR-96 |
| 既定の期間 | 直近 28 日 | FR-01、NFR-98 |
| 立ち上がり（曲線） | 記事を公開してから N 日間の累積 PV の推移。画面では「公開からの読まれ方」 | M-18、FR-23 |
| 7 日 PV、30 日 PV | 公開後 7 日間、30 日間の累積 PV。画面では「最初の 1 週間で / 最初の 1 か月で読まれた回数」 | M-20 |
| 全記事の中央値・四分位、帯 | 母集団（直近 12 か月に公開、N 日以上経過、広告を除く、30 本以上）の N 日累積 PV を並べたときの中央値と 25%・75% 点。画面では「多くの記事はこの範囲」。帯の中の位置は「よく読まれています / 多くの記事と同じくらい / これから」の 3 区分 | M-19、FR-21、FR-23、FR-31 |
| 母集団 | 中央値・四分位を計算する対象の記事群。30 本未満なら全期間に広げ、それでも未満なら「まだ比較できません」 | M-19、Q-14（確定） |
| 「普通の記事」の帯 | 全体ダッシュボードに出す 1 行。「このサイトの多くの記事は、公開から 30 日で ◯〜◯回（真ん中は ◯回）読まれます」（「だいたい」は「ほとんど」に読めるので使わない） | M-27、FR-17 |
| 到達のお知らせ | 記事の累積が 500、1,000、5,000、10,000 回に初めて達した日と、公開 1 年以降も読まれていることの表示 | M-23、FR-23、FR-31 |
| 自分の過去との比較 | 著者自身の記事の 30 日 PV の中央値を基準にした比較 | M-24、FR-23、FR-31 |
| 鮮度区分 | 新着（1 か月以内）、1〜3 か月、長く読まれている（3 か月以上）。旧称: 新着、既刊、ロングテール | M-21 |
| 最近読まれている、久しぶりに読まれた | 公開 15 日以上、直近 7 日 20 回以上、前 4 週の週平均の 2 倍以上の記事。「久しぶり」は加えて公開 91 日以上。肯定だけを出す | M-22、FR-34 |
| 伏せ値 | 小さな集計値を格納時に「5 未満」に置き換えたもの。しきい値 T = 5。画面では一次伏せ・二次伏せの区別なく「—」とし、セルの近くに「伏せ値」と添える（Q-33）。格納する組み合わせは記事 × 内訳軸 1 つまでで、組み合わせごとの粒度と適用の有無は 05_non_functional.md §4.1 の表に従う。記事 × 日の読まれた回数と、合計・累積は伏せない。GA4 が行を返さない区分は 0 として格納し、0 も伏せない（0 は個人に結び付かない。D-16） | NFR-33、FR-73、05 §4.1、D-16 |
| 二次伏せ | 排他的な区分（流入チャネル、SNS 種別、デバイス、初めて / また来た、地元の読者の目安）で伏せたセルが 1 つだけのとき、合計から逆算できないようにもう 1 つのセルも伏せること。追加して伏せる候補は、伏せていないセルのうち値が T 以上で最小のセル（0 や 5 未満のセルを選ぶと、伏せた 2 セルの和がそのまま伏せた値になるため。該当がなければ追加しない。設計レビュー M-1、D-16）。著者 × 内訳軸 では、同じ区分で伏せた記事のセルが 1 本だけのとき著者のセルも伏せる（階層差分。設計レビュー M-2）。画面では一次伏せと同じ「—」で出し、二次伏せであることは示さない（示すと「伏せたセルのうち 1 つは 5 以上」と分かり、合計との差から値を狭められるため。Q-33、ADR 0003） | NFR-33、05 §4.1、D-16 |

## 5. 構成要素と技術用語

| 用語 | 意味 |
