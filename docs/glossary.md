# 用語集

- 状態: 草案
- 更新日: 2026-11-03

この文書は、運営者・ライターの言葉と GA4 の指標名のずれを残すためのもの。要件（docs/requirements/02_metrics.md）の指標 ID と対応させる。

## 1. 運営者の言葉と GA4 の指標名の対応

| 運営者・ライターの言葉 | この BI での名称 | GA4 Data API の名前 | 指標 ID | 注意 |
| --- | --- | --- | --- | --- |
| アクセス数 | 表示回数（PV） | screenPageViews | M-01 | 仮置き。何を指すかは Q-01 で確認中。同じ人が 3 回読めば 3 と数える |
| PV、ページビュー | 表示回数（PV） | screenPageViews | M-01 | GA4 の管理画面では「表示回数」と表記される |
| 訪問数、来訪数 | セッション数 | sessions | M-02 | 1 回の訪問。30 分操作がないと別のセッションになる |
| 訪問者数、人数、UU | ユーザー数 | activeUsers | M-03 | GA4 の標準レポートは activeUsers（エンゲージメントのあったユーザー）を使う。totalUsers とは別。日別の値を足しても期間の人数にならない |
| 新規の人 | 新規ユーザー数 | newUsers | M-04 | 初めてサイトを訪れたユーザー |
| リピーター | リピーター | newVsReturning = returning | M-15 | 以前に訪れたことがあるユーザー |
| 滞在時間、読まれた時間 | 平均エンゲージメント時間 | userEngagementDuration ÷ activeUsers | M-06 | タブが前面にあった時間の合計を人数で割る。UA の「平均ページ滞在時間」とは定義が違う |
| 直帰率 | 直帰率 | bounceRate | M-08 | GA4 では「エンゲージメントのなかったセッションの割合」。UA の直帰率とは定義が違う |
| ちゃんと読まれたか | エンゲージメント率 | engagementRate | M-05 | 10 秒以上、または 2 ページ以上、またはコンバージョンのあったセッションの割合 |
| 最後まで読まれたか | スクロール到達ユーザー数 | scrolledUsers | M-09 | ページの 90% までスクロールしたユーザー数 |
| どこから来たか | 流入チャネル | sessionDefaultChannelGroup | M-10 | 検索・SNS・直接・参照・その他の 5 区分にまとめる |
| どのサイトから来たか | 参照元ドメイン | sessionSource | M-12 | ページ単位の完全な URL（pageReferrer）は取得も表示もしない |
| 検索から | 検索（Organic Search） | sessionDefaultChannelGroup = Organic Search | M-10 | 検索語は Search Console にしかない（Q-09） |
| SNS から | SNS（Organic Social） | sessionDefaultChannelGroup = Organic Social | M-11 | Instagram、Facebook、X、LINE、その他に分ける |
| スマホ・PC | デバイス種別 | deviceCategory | M-13 | mobile / desktop / tablet |
| 地域、どこの人 | 地域（都道府県・市） | region、city | M-14 | 市までの粒度。区（高津区）は取れない見込み（Q-11） |
| 入口の記事 | ランディングページ | landingPage | M-17 | セッションの最初に見たページ |

## 2. GA4 の用語

| 用語 | 意味 |
| --- | --- |
| GA4 | Google アナリティクス 4。対象サイトは gtag.js（測定 ID G-79CFGF83VT）で計測している |
| プロパティ | GA4 でサイトごとに作る計測の単位。Data API はプロパティ ID（数字）で指定する。ID はリポジトリに置かない |
| GA4 Data API | GA4 の集計値を取り出す API。本 BI の主なデータソース（DS-01） |
| 次元（ディメンション） | 集計を切る軸。date、pagePath、deviceCategory など |
| 指標（メトリクス） | 集計する値。screenPageViews、sessions など |
| pagePath | URL のパス部分（例: /4800/）。クエリ文字列を含まない。記事 ID との突き合わせに使う |
| エンゲージメント | 10 秒以上の滞在、2 ページ以上の閲覧、コンバージョンのいずれかがあること |
| データの確定 | GA4 の日次データは処理に通常 12 時間、24〜48 時間かかることがあり、遅れて届くデータは最大 7 日。確定前は値が変わる |
| タイムゾーン | GA4 のレポートはプロパティに設定したタイムゾーンで日付を切る。Asia/Tokyo かは Q-07 で確認中 |
| Workload Identity Federation（WIF） | 鍵ファイルを使わずに GitHub Actions から Google の API を呼ぶための認証方式。サービスアカウントの JSON 鍵は作らない |

## 3. WordPress の用語

| 用語 | 意味 |
| --- | --- |
| 投稿（post） | ブログ記事。本 BI で「記事」と呼ぶもの。URL は https://takatsu-connect.com/<記事 ID>/ |
| 固定ページ（page） | 「高津コネクトについて」などの記事でないページ。集計に含めるかは Q-17 |
| 著者（author） | 投稿を書いた WordPress ユーザー。本 BI では「ライター」と同じ意味。保存・表示するのは表示名と著者ページ URL（slug）だけ |
| 表示名 | 著者がサイト上で名乗っている名前。実名風とハンドルが混在する |
| カテゴリ | 記事の分類。二階層（親: イベント、記事、マップ、広告）。同名の子が別の親にあるため「親 > 子」のパスで表示する |
| タグ | 記事を横断して束ねるラベル。シリーズ企画（例: 多摩川カレーグランプリ）に使われている |
| WP REST API | WordPress が公開する API（/wp-json/wp/v2/）。記事のメタデータの取得元（DS-02） |
| 公開状態 | publish（公開）だけが REST API に出る。下書き、非公開、パスワード付きは出ないため BI にも入らない |
| wp-ulike | 「いいね」ボタンのプラグイン |
| add-to-any | SNS シェアボタンのプラグイン |

## 4. この BI で使う用語

| 用語 | 意味 | 関係する ID |
| --- | --- | --- |
| 基準日 | BI に表示されているデータの最終日。通常は前日（D-1） | NFR-02、FR-02 |
| 前期間比 | 選んだ期間の直前の同じ長さの期間との比較。月別は前月と前年同月 | FR-01 |
| 立ち上がり（曲線） | 記事を公開してから N 日間の累積 PV の推移 | M-18、FR-23 |
| 7 日 PV、30 日 PV | 公開後 7 日間、30 日間の累積 PV | M-20 |
| 全記事の中央値・四分位 | 比較対象の記事群（母集団は Q-14）の N 日累積 PV を並べたときの中央値と 25%・75% 点 | M-19 |
| 新着、既刊、ロングテール | 公開後 30 日以内、31〜90 日、91 日以上の記事の区分 | M-21 |
| 最近読まれている、久しぶりに読まれた | 直近 7 日の PV が前 7 日より大きく伸びた記事。判定基準は Q-18 | M-22、FR-34 |
| 伏せ値 | 小さな集計値を格納時に「T 未満」に置き換えたもの。しきい値 T は Q-02 | NFR-33 |
| 順位表 | ライターを数値で並べた表。既定では出さない | NFR-36、FR-35 |
| 日次バッチ | 1 日 1 回、GA4 と WP REST API からデータを取り Supabase に格納する処理 | FR-70 |
| バックフィル | 初回に過去分をまとめて取り込むこと | FR-75 |
| 記事以外 | 投稿に対応しないページ（トップ、一覧、著者ページ、固定ページ）をまとめた区分 | Q-17 |

## 5. 構成要素と技術用語

| 用語 | 意味 |
| --- | --- |
| Supabase | 集計値の格納先。依頼者の決定。ブラウザからは読まず、Vercel のサーバー側からだけ読む |
| Vercel | BI の Web アプリの配信先。依頼者の決定 |
| GitHub Actions | 日次バッチの実行環境。依頼者の決定。public リポジトリで動く |
| RLS | Row Level Security。Supabase の表ごとに読める行を制限する仕組み |
| service role キー | Supabase の書き込み権限を持つキー。バッチだけが使い、ブラウザに渡さない |
| noindex | 検索エンジンに載せない指示。公開の形は Q-04 |
